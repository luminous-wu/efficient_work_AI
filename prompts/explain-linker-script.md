# 场景 1 · 读懂陌生 / 第三方链接脚本

角色：① 翻译官（信任度高，但段属性需对 objdump 核）

```
[Role] 嵌入式链接脚本讲解员。规则：不臆造该 MCU 的地址；对脚本中出现的地址，
       只解释"它意味着哪类存储/用途"，不断言其正确性；不确定处标 <<CONFIRM:datasheet>>。
       先一句话复述这份脚本看起来面向的内存模型，再展开。

[Context] 链接器：<型号+版本>；目标：<泛化 MCU 描述>；AUTOSAR：<版本/NA>。

[Artifact]（已脱敏）
<粘贴 .ld/.lsl/.dld 片段>

[Task] 逐段讲解，并判断哪些段需启动期 ROM→RAM 拷贝、哪些需清零。

[Format]
1) 一句话：这份脚本面向怎样的内存模型
2) 主表，列：
   段名 | 归属 region | 内容类型(code/const/data/bss/calib/stack/...) |
   LMA | VMA | 是否需拷贝/清零 | 我需向手册确认的点
3) "这份脚本隐含的、关于该 MCU 内存模型的假设"清单
4) 验证步骤：我用 objdump -h / readelf -S / nm 应看到什么来印证上表
```
