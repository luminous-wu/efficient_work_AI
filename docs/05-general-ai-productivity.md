# 05 · 通用 AI 提效（不限领域的工作日常）

前四章解决"链接脚本这个细分方向怎么用 AI"。本章解决另一半——**作为一名软件工程师，一天里那些与领域无关的工作（写代码、调试、读资料、写文档、沟通、规划、学习），如何用 AI 系统性提速**。

定位：本章是**水平能力**，与第 02 章的垂直手册并行。两者共用第 01 章的方法论内核（角色意识、验证纪律、D-D-V-I），只是验证强度不同——通用任务出错代价低，可以更激进地用。

---

## 0. 一个判断框架：这个任务该不该用 AI、用到什么程度

每个任务先过这三问，避免"为用而用"或"该用不用"：

1. **任务是"生成"还是"决策"？** 生成（草稿、样板、解释、翻译、整理）→ 大胆用；决策（架构选型、是否上线、安全相关）→ AI 只做信息收集和反方观点，结论你拍。
2. **错了好不好发现、好不好回滚？** 容易（代码有测试、文档你会通读、命令在沙箱）→ 放手；不容易（直接发出去的邮件、生产操作、对外承诺）→ 必审。
3. **你做要 X 分钟，验证 AI 的产出要多久？** 若"验证时间 < 自己从零做" → 用 AI 划算；若"验证比自己做还久"（典型：你不熟的领域让 AI 写复杂逻辑）→ 别用，或先用它教你。

> 一句话：**生成类、易回滚、验证成本低 → AI 甜区，激进用；决策类、难回滚、验证成本高 → 谨慎或只当参谋。**

## 1. 七大通用场景 + 用法

### ① 写代码 / 脚手架
- **甜区**：样板代码、重复结构、数据结构转换、正则、一次性脚本、把伪代码变实现、补单元测试、写 CLI/解析器。
- **关键技巧**：给 **上下文 + 约束 + 期望签名/接口**，而不是只说"写个 X"。让它先列方案要点你确认，再生成（避免它跑偏后大段返工）。
- **验证**：跑测试 / 跑一次 / 读关键路径。不熟的库尤其要核 API 是否真实存在（AI 会编造看似合理的函数名）。

### ② 调试 / 排错
- **用法**：贴**报错全文 + 最小可复现片段 + 你已试过什么**，让它给"按概率排序的假设 + 每个假设如何最快证伪"。
- **高杠杆**：把它当**橡皮鸭**——逼自己把问题讲清楚，常常讲到一半自己就发现了。
- **陷阱**：别让它"猜着改"。要它给定位方法，你来定位。

### ③ 读代码 / 读资料 / 快速进入新领域
- **用法**：粘陌生代码/文档让它"先讲整体结构和数据流，再逐块解释，最后列我应重点验证的假设"。学新框架让它给"最小心智模型 + 该精读官方文档哪几节"。
- **这是 AI 性价比最高的用法之一**——把"建立理解"的时间砍掉一大半。
- **验证**：概念性结论回查权威源（官方文档/规范），别把 AI 讲解直接当事实引用。

### ④ 写作 / 文档 / 沟通
- **甜区**：技术文档、设计说明、PR 描述、周报、邮件、把零散要点结构化、改语气、中英互译、长文摘要。
- **技巧**：**你给事实和观点要点，AI 负责组织和措辞**——不要让它编内容。要求"只组织我给的信息，缺失处标 [需补充]"。
- **验证**：对外/对上的内容必通读，确认事实准确、语气得体、没有 AI 腔。

### ⑤ 规划 / 拆解 / 决策支持
- **用法**：把大任务丢给它做 WBS 拆解和风险清单；做技术选型时让它列**候选项对比表 + 各自代价**，并要求它**给出反对你倾向方案的理由**（对抗性思考，破除确认偏误）。
- **红线**：决策是你的。AI 扩大视野、暴露盲点，不替你拍板。

### ⑥ 学习 / 能力成长
- **用法**：用 AI 做"个性化导师"——出练习、解释你的错误、用费曼法考你（你讲它挑漏洞）、按你现有水平定制学习路径。
- **关键**：让它**考你**而不是只喂你答案。被动接收 ≠ 学会（详见第 4 节防退化）。

### ⑦ 自动化重复劳动
- **用法**：识别每周重复的机械活（整理日志、批量改文件名、生成报告、格式转换、数据清洗），让 AI 写脚本一次性解决，你审后固化。
- **复利最高的一类**：今天花 30 分钟让它写个脚本，省掉未来每周 20 分钟。

## 2. 通用提示词四原则（比领域版更轻量）

领域任务要"四要素严结构"；通用任务用这四个轻原则即可：

1. **给上下文，别给指令就完事**：差"帮我写个函数排序"；好"这是数据结构和调用场景<贴>，写个按 X 排序的函数，需稳定排序，Python 标准库"。
2. **要它先复述/先列纲要再展开**：复杂任务加一句"先用三行讲你的方案，我确认后再写"——拦截跑偏，省返工。
3. **指定输出形态**：表格 / diff / 分步 / 仅代码无解释 / 200 字内。形态对了，可用性翻倍。
4. **迭代而非一次到位**：把 AI 当对话伙伴。第一版当草稿，用"这里改成…/这部分太啰嗦/换个思路"逼近，比憋一个完美提示更快。

补充高频技巧：
- **角色设定**有用但别迷信——"你是资深 X"主要影响风格和侧重，不会变出它不知道的知识。
- **少样本**：给 1-2 个"输入→期望输出"例子，比长篇描述更精准（尤其格式化/转换任务）。
- **明确说"不知道就说不知道，不要编"**——能显著降低幻觉，尤其问事实和 API 时。

## 3. 工具与工作流落地

### 三类工具各司其职
| 类型 | 用途 | 何时用 |
|---|---|---|
| **对话式助手** | 思考、写作、解释、规划、单点问答 | 离开代码库的思维和文字工作 |
| **IDE 内联助手** | 补全、行内重构、选中即改、贴着代码问 | 写代码的主场 |
| **命令行 Agent**（如 Claude Code） | 多文件改动、跑测试、查代码库、自动化闭环 | 跨文件任务、自动化、"读-改-验"循环 |

选择原则：**任务在哪里发生，就用最贴近那里的工具**——纯思考用对话式，改代码用 IDE/Agent，别拿对话式手抄代码来回倒。

### 一天的典型嵌入点
- **晨间规划**：把今天要做的事丢给 AI 拆解、估时、标依赖和风险，5 分钟出可执行清单。
- **进入任务**：不熟的代码/需求先让 AI 讲一遍建立心智模型，再动手。
- **写/调过程中**：IDE 助手补样板、Agent 跑测试、卡住时橡皮鸭。
- **收尾**：让 AI 起草 PR 描述/提交信息/文档（你给已验证的要点）。
- **周末复盘**：让 AI 帮你从本周记录里提炼"哪些重复活该自动化"，挑一个下周做掉。

### 把高频提示沉淀成资产
和领域版一样：好用的提示存成片段库（PR 描述模板、调试模板、代码审查模板、学习考核模板）。**复用提示是个人复利**。

## 4. 通用红线与防退化（轻领域、但不能不管）

通用任务出错代价低，所以纪律比领域版松——但有三条不能破：

1. **对外/不可回滚的内容必过人眼**：发出去的邮件、PR、对客户/对上承诺、生产命令。AI 起草，你负责。
2. **事实与代码必验证**：AI 会自信地编 API、编数据、编引用。涉及事实就交叉核对，涉及代码就跑起来。
3. **防能力退化（最隐蔽、最重要）**：
   - 警惕"看得懂但写不出"——长期只读 AI 代码不自己写，基本功会萎缩。
   - 重要的东西用 AI **考你**，不只是喂你答案；学完能脱离 AI 复述/重做才算学会。
   - 关键技能定期"无 AI 练习"，像运动员保持手感。AI 是杠杆，支点（你的判断力）塌了杠杆没意义——这点与 `docs/04` 的信念完全一致。

> 反模式速记：把 AI 草稿当成品直接发 / 让它猜着改代码 / 不熟的领域让它写复杂逻辑还不验证 / 只接收不输出导致越用越废。

## 5. 一页纸总结

```
该不该用：  生成+易回滚+验证便宜 → 激进用；决策+难回滚+验证贵 → 当参谋
七场景：    写码 调试 读懂 写作 规划 学习 自动化 —— 自动化复利最高
提示四原则：给上下文 / 先列纲要 / 指定形态 / 迭代逼近（+"不知道别编"）
选工具：    思考用对话式，改码用IDE/Agent，自动化用Agent
红线：      对外内容必审 / 事实代码必验 / 用AI考你防退化
心法：      AI放大判断力不产生判断力 —— 与 docs/04 同一信念
```

> 通用与领域不是两套方法，是**同一方法论在不同风险等级下的两种档位**。通用档放手提速，把省下的精力，投回到 `docs/02` 那些不能松手、决定你不可替代性的地方。
