# 用 AI 高效工作：汽车电子区域控制器 / OS 链接脚本方向

> 面向角色：汽车电子区域控制器（Zone Controller）软件开发工程师
> 技术栈定位：商用编译器（Green Hills MULTI / TASKING VX / IAR）+ AUTOSAR Classic + MCU 厂商生态（Infineon AURIX、NXP S32 等）
> 使用定位：**个人学习与能力提升为主**，不直接把量产受控代码喂给云端 AI

本仓库是一套「系统化的 AI 高效工作设计」，不是零散技巧合集。它把"如何让 AI 真正提升你这个细分方向的产出"拆成四层，逐层可落地、可复用、可度量。

---

## 0. 一句话核心观点

> **AI 不会替你做链接脚本和内存布局的决策，但能把你从"读手册、抠语法、查地址、写脚本、整理文档"里解放出来，让你把时间花在"做正确的内存架构决策"上。**

链接脚本方向的特殊性决定了使用 AI 的方式与一般业务开发完全不同：

- **错一个地址 = 整车不启动 / 偶发踩内存 / 功能安全失效**，所以 AI 的所有输出在本方向必须**强制人工对照权威信源验证**（数据手册、.map 文件、芯片 memory map）。
- 知识高度**碎片化且厂商私有**（每家编译器链接脚本语法不同、每颗 MCU 内存模型不同），AI 最大价值在于**快速建立心智模型 + 跨厂商翻译 + 自动化辅助工具**，而非直接生成可量产脚本。
- 工作产物（.ld / .lsl / .dld、.map、MemMap、Os 配置）天然适合 AI 处理：**纯文本、强结构、规则明确**。

## 2. 如何使用本仓库

1. **第一周**：通读 `01-methodology.md`，照着搭好 `03-tooling-setup.md` 的环境（重点是离线/脱敏链路）。
2. **日常**：遇到具体任务 → 查 `02-domain-handbook.md` 对应场景 → 套 `prompts/` 模板 → **按方法论里的验证清单核对**。
3. **每月**：用 `04-growth-roadmap.md` 的指标自评，调整重心。

---

## 3. 三条贯穿全程的红线（务必先记住）

1. **地址 / 大小 / 对齐 / 段属性，AI 说的一律不信，以数据手册和 .map 为准。** AI 用来"提出假设"和"加速验证"，不用来"下结论"。
2. **量产受控信息不出域。** 即使是个人学习，也用脱敏后的抽象问题（见方法论第 5 节），把"对客户/对芯片保密"练成肌肉记忆。
3. **AI 是放大器，不是替代品。** 它放大你已有的判断力；判断力本身（看懂 memory map、理解功能安全分区）仍需你自己长出来——这正是 `04-growth-roadmap.md` 的目的。
